## 0. 环境实测（2026-09-03）
- 系统：Deepin 25 (crimson)，XDG_SESSION_TYPE=x11 ✅
- 依赖：qt6-base-dev / libpoppler-qt6 / libatspi2.0-dev / espeak-ng 均已安装 ✅
- 目标应用：deepin-reader（Deepin 25 文档阅读器）
- 安装形态：玲珑包 org.deepin.reader v6.5.58.1（非 deb，容器化运行）——**无需 deb，实测兼容** ✅
- 实测结论 1：窗口标题固定为「文档查看器」，**不含文件名/页码** → 废弃"标题解析页码"方案
- 实测结论 2：`/proc/<PID>/fd` 可直接读取当前打开的 PDF 完整路径（fd 透传宿主路径）✅
- 实测结论 3：`~/.local/share/deepin/deepin-reader/user.db`(SQLite) 有 operation 表(filePath, currentPage)，记录每本书的阅读位置；**翻页时不实时写库**（退出/切书才写），可作初始页码，不能作实时页码源
- 实测结论 4：at-spi2-core 组件未安装（bus-launcher 缺失）、无障碍开关关闭 → **AT-SPI 实时页码本机不可用**；若用户接受「安装 at-spi2-core + 开启无障碍」，可再尝试，但玲珑容器内能否访问存疑（高风险，降为 P1 可选）
- 玲珑注意：外层 ll-cli 进程 + 内层 deepin-reader 进程，需匹配内层进程名（`deepin-reader`）取 fd

## 2. 技术栈（不变）
C++17 + Qt6（Widgets 托盘 + QWidget 面板）+ Poppler-Qt6 + espeak-ng + Xlib；CMake ≥3.16；deb 手动打包。

## 3. 文档识别 + 页码同步策略（v0.3 实测修订）
### 3.1 文档识别（已实测可行）
1. 枚举进程，匹配 `deepin-reader`（内层真实进程，非 ll-cli）
2. 扫描 `/proc/<PID>/fd`，筛出指向 `.pdf` 的符号链接 → 获得当前打开文件绝对路径
3. 监听 `_NET_ACTIVE_WINDOW` 感知切换；轮询 fd 变化（0.5~1s）感知打开/关闭/换书

### 3.2 页码控制（v0.4 用户确认：不要实时跟随）
1. **初始页码**：从 user.db operation 表按 filePath 查 currentPage（上次阅读位置）✅ 已验证可读
2. **朗读推进**：按固定页序自动推进（第 N 页读完自动 N+1），本工具独立维护页码，不依赖阅读器
3. **手动控制**：面板提供 页码输入框 / 上一页 / 下一页 / 暂停后指定页，用户随时手工设定
4. **校准配合**：用户在阅读器翻到某页 → 在面板输入同一页码 → 本工具从该页开始朗读；面板实时显示当前朗读页码供对照校验

## 4. 模块划分
- M1 WindowWatcher：X11 枚举/标题解析/激活切换
- M2 DocManager：当前文档 + 页码状态 + 事件
- M3 TtsEngine：espeak-ng 逐页朗读循环
- M4 Tray+Panel：托盘菜单 + 右下角悬浮面板（播放/暂停/上一页/下一页/语速/页码）
